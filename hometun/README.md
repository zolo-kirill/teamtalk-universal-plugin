# Домашний туннель для YouTube

Дополнение к universal plugin для серверов, чей дата-центр блокирует YouTube.
Бот качает ролики через домашний интернет владельца: на домашнем ПК поднимается
локальный SOCKS-прокси, а на сервер уходит reverse-туннель по SSH. yt-dlp на
сервере ходит через этот туннель, и YouTube видит домашний IP — без
дата-центровых ограничений и бот-проверок.

Работает так:

```
домашний ПК (Windows)                 сервер бота (Linux)
┌───────────────────────────┐         ┌──────────────────────────────┐
│ gost: socks5 127.0.0.1:1088 │──plink──▶│ sshd принимает reverse      │
│ (выход в домашний интернет)│ -R 1080  │ 127.0.0.1:1080 → 127.0.0.1:1088
└───────────────────────────┘         │ yt-dlp → socks5://127.0.0.1:1080
                                      └──────────────────────────────┘
```

- `gost` поднимает на ПК локальный SOCKS-прокси (порт 1088).
- `plink` (PuTTY) держит на сервере reverse-туннель: порт 1080 на сервере
  пробрасывается на SOCKS-прокси домашнего ПК.
- Бот перед каждым скачиванием YouTube сам проверяет туннель: задана
  переменная `YT_TUNNEL=socks5://127.0.0.1:1080`, и если её порт на сервере
  слушается (программа на домашнем ПК открыта) — YouTube-трафик yt-dlp идёт
  через туннель.

Бот переключается на лету, без перезапуска: открыл программу на ПК — следующее
скачивание идёт через домашний интернет; закрыл — бот возвращается на обычный
канал сервера (напрямую, или через `YT_PROXY`, если задан резервный прокси).
Туннель живёт, пока на домашнем ПК открыта программа и компьютер включён.

## Состав

- `server/setup.sh` — установка туннельного пользователя на сервере бота
  (создаёт ключ, правит `authorized_keys` с ограничением только на
  forward-порт, печатает всё нужное для клиента).
- `client/` — программа для домашнего ПК на Windows:
  - `tunnel.ps1` + `start-tunnel.bat` — сам туннель, настраивается по данным
    сервера при первом запуске (или файлом `config.txt`);
  - `config.example.txt` — образец настроек;
  - `README.txt` — инструкция для пользователя домашнего ПК.

## Установка на сервере

На сервере бота (от root):

```bash
sudo bash server/setup.sh                 # пользователь hometun, порт 1080
sudo bash server/setup.sh --user tun --remote-port 1090   # свои значения
```

Скрипт напечатает: код безопасности сервера (строку `host_key`), приватный ключ
и напоминание, что в окружении бота нужно задать `YT_TUNNEL` и перезапустить его.

Для universal plugin переменные окружения задаются в секретах бота (`.env`),
например:

```
YT_TUNNEL=socks5://127.0.0.1:1080
```

Как это работает в `bot.py` (функция `_yt_proxy`, см. секцию про прокси в коде):
перед каждым скачиванием YouTube бот проверяет, доступен ли порт из `YT_TUNNEL`.
Доступен — качает через туннель (домашний интернет). Недоступен — качает обычным
каналом: через `YT_PROXY`, если он задан, иначе напрямую; в режиме без `YT_TUNNEL`
прежнее поведение не меняется (`YT_PROXY`, иначе мост `TG_PROXY`).

Если хочешь, чтобы при закрытом туннеле бот не шёл напрямую (где дата-центр может
блокировать YouTube), а через резервный прокси — задай `YT_PROXY` отдельно,
например `YT_PROXY=<адрес твоего резервного прокси>`.

## Подготовка клиента

В папку `client/` нужно добавить три программы (в git они не хранятся):

| Файл | Откуда |
|---|---|
| `plink.exe` | [PuTTY download page](https://www.chiark.greenend.org.uk/~sgtatham/putty/latest.html) — `plink.exe` (64-bit) |
| `gost.exe` | [ginuerzh/gost v2.11.5](https://github.com/ginuerzh/gost/releases/tag/v2.11.5) — `gost-windows-amd64-2.11.5.zip`, внутри `gost.exe` |
| `hometun.ppk` | приватный ключ, выданный `setup.sh`, сконвертированный в `.ppk` (см. ниже) |

Конвертация ключа в формат PuTTY (на Windows, программой `puttygen` из того же
пакета PuTTY):

```
puttygen tun_key -o hometun.ppk
```

Файлы `config.txt` и приватный ключ создаются при установке у конкретного
владельца и в git не попадают (см. `.gitignore`).

## Первый запуск клиента

1. Положите `hometun.ppk` в папку `client/`.
2. Запустите `start-tunnel.bat`.
3. Программа задаст вопросы (адрес сервера, логин, код безопасности `host_key`,
   порт на сервере) и сохранит ответы в `config.txt` рядом с собой.
4. При успехе программа сообщит «Подключено!».

Сменить сервер — удалить `config.txt` и запустить снова, либо отредактировать
`config.txt` блокнотом. Формат — простые строки `ключ = значение`.

Проверка на сервере, что туннель поднят (порт слушается и трафик уходит на
домашний IP):

```bash
ss -tlnp | grep :1080
curl -s -x socks5h://127.0.0.1:1080 https://api.ipify.org   # домашний IP
```

## Безопасность

Туннельный пользователь на сервере не имеет шелла (`nologin`), а в
`authorized_keys` ему разрешён только `port-forwarding` и только на указанный
локальный адрес и порт (`restrict,port-forwarding,permitlisten="127.0.0.1:1080"`).
Приватный ключ хранится только у владельца домашнего ПК; скомпрометированный
ключ отзывается удалением строки из `authorized_keys` на сервере.
