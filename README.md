# teamtalk-universal-plugin

Бот для сервера TeamTalk 5. Воспроизводит музыку и другое аудио в голосовой канал, следит за сервером и сообщает о событиях в Telegram, блокирует ботнет-подключения и обрабатывает заявки на новые учётные записи.

Аудио передаётся в канал как голос (вставка аудиоблоков), поэтому звуковая карта не требуется — достаточно ffmpeg. Поддерживается стерео: при стерео-кодеке канала звук передаётся без изменений, 48 кГц.

Управление — слэш-командами, едиными для TeamTalk и Telegram. В TeamTalk команды отправляются боту личным сообщением.

## Музыка

- `/play` и `/p <запрос>` — поиск и воспроизведение по текстовому запросу; голые `/play` и `/p` — пауза и возобновление. Ссылки эти команды не принимают.
- `/u <ссылка>` — воспроизведение ссылки. Вставленная ссылка (в личном сообщении боту или в канале) также запускает воспроизведение.
- Ссылка на плейлист YouTube или Яндекс.Музыки ставит в очередь весь плейлист.
- `/playlist` — текущий плейлист, постранично.
- `/stop` — остановка; `/skip` — пропуск трека; `/v <5–100>` — громкость; `/sf 30` и `/sf -30` — перемотка вперёд и назад; `/sb 66` — перемотка назад на 66 секунд.
- `/radio` — радиостанции; `/fav` — избранное (добавление через `/fav +` или `f +`).
- `/lf <путь>` — воспроизведение файла с диска бота; `/dl` — выдача текущего трека файлом в канал (для радио и потоков недоступно). Трек загружается без перекодирования (обычно opus/webm — быстрее и без потери качества); mp3 собирается на лету только при выдаче через `/dl`.
- `/vo` — озвучивание названия трека перед началом воспроизведения.
- Сервисы: `/sv yt` — YouTube, `/sv ym` — Яндекс.Музыка. По умолчанию поиск и воспроизведение выполняются на YouTube; для Яндекс.Музыки требуется токен (см. «Конфигурация»). Прямые ссылки на треки YM также воспроизводятся.
- При сбое загрузки бот автоматически пробует резервные клиенты YouTube; раз в сутки проверяет и обновляет yt-dlp. Возрастные видео YouTube с серверного адреса не воспроизводятся: сервис требует входа в аккаунт и ограничивает сессии с серверных IP.
- `/login` — статус входа в YouTube и инструкция по входу. Бот принимает экспорт кук из браузера (Netscape-формат, например расширение Get cookies.txt): текст экспорта отправляется боту в Telegram или файлом `.txt` — бот сохраняет его в `yt_cookies.txt`, проверяет и использует. Ограничение возрастных роликов с серверного IP сохраняется — это ограничение YouTube.

## Функции на сервере

- Личные сообщения пользователей (не команды) пересылаются администраторам в Telegram; ответ из Telegram доставляется пользователю в личное сообщение.
- События входа/выхода, кики и заявки регистратора отправляются в Telegram (при настроенном боте-реле).
- Исключения из приветствий и анонсов входа/выхода задаются в `telegram.ignore_nicks` (по нику, например `stats`) и `telegram.ignore_usernames` (по логину).
- `/sub` — подписка пользователя на уведомления о входах/выходах; `/sub mus` — на присылку играющих треков в личное сообщение.
- `/online` — список присутствующих на сервере; в Telegram каждый пункт сопровождается кнопками «написать», «кикнуть», «забанить».
- `/net <текст>` — broadcast-сообщение всем пользователям сервера.
- `/admins`, `/subs` — списки администраторов и подписчиков. Назначение владельца выполняется только правкой `telegram.owner_user_id` в конфиге.
- Регистратор — отдельный Telegram-бот. Пользователь отправляет ему логин и пароль, администратор подтверждает заявку — бот создаёт учётную запись на сервере и присылает пользователю файл `.tt`. Администратор также может создать учётную запись командой `/create`.
- При изменении прав учётной записи бот отключает активные сессии под ней для повторного входа с новыми правами: сервер применяет права при логине, активные сессии сохраняют прежние. Секция `account_watch` в конфиге.
- `autokick` — учётные записи, ники и IP-адреса, которые выкидываются сразу при входе (кик без бана). Список задаётся в секции `autokick` конфига; о каждом срабатывании бот сообщает в Telegram.

## Защита от ботнетов

На публичные TeamTalk-серверы выполняются автоматизированные подключения под гостевой учёткой. Секция `guard` в конфиге проверяет гостевые подключения (учётки из `guest_logins` и пустой логин) и отклоняет те, которые:

- выполняют вход с пустым ником, ботнет-ником, ником длиннее `max_nick_len` символов или с нецензурными выражениями в нике;
- выполняют множественные подключения с различных IP за короткий интервал (`burst`);
- подключаются из стран, не входящих в разрешённый список (`geo`, по умолчанию Россия).

Доверенные пользователи (сам бот, администраторы, легитимные боты) указываются в `trusted` — защита их не затрагивает. Обнаруженные боты отключаются и, при наличии прав администратора, банятся по IP. Отчёт о срабатываниях отправляется в Telegram одним сообщением на всплеск, а не на каждый инцидент.

## Конфигурация

Настройки хранятся в двух файлах рядом с ботом: `config_default.json` (эталон, входит в репозиторий) и `config.json` (рабочий, поверх эталона; в git не хранится, поскольку содержит токены и пароли). Бот читает `config.json`, затем переменные окружения, затем значения по умолчанию.

Секции конфига:

- `server` — параметры подключения к TeamTalk: адрес, порты, ник, логин, пароль, канал.
- `playback` — громкость по умолчанию и устройство вывода (`pulse_sink`, при воспроизведении через PulseAudio).
- `runtime` — сервис по умолчанию, команды при запуске, лимиты плейлиста.
- `services` — токен Яндекс.Музыки и пути к файлам кук YouTube и Rutube.
- `telegram` — токен бота-реле, идентификатор владельца, чат уведомлений, имя сервера.
- `welcome` — текст приветствия с правилами.
- `registration` — настройки бота-регистратора.
- `account_watch` — контроль прав учётных записей: `enabled`, `interval_sec` (периодичность проверки, по умолчанию 10), `notify_owner` (отправка уведомлений об отключениях в Telegram).
- `guard` — защита от ботнетов (см. выше).
- `autokick` — кто выкидывается при входе: `logins` (логины учётных записей, точное совпадение), `nicks` (подстрока ника), `ip_prefixes` (начало IP-адреса).

Ник, сервис и громкость изменяются на лету командами `/cn`, `/sv`, `/v` и сохраняются до перезапуска. Команда `/sc` записывает текущие ник, сервис и громкость в `config.json`. После ручного изменения конфига бот перезапускается командой `/rs`.

Секреты хранятся отдельно в `../.secrets/.env` (папкой выше бота): токены Telegram-ботов и TeamTalk-переменные. Токен Яндекс.Музыки — в `services.ym.token`. Куки YouTube (Netscape-формат) — в файле `yt_cookies.txt`, путь указывается в `services.yt.cookiefile_path`.

## Установка и запуск

Требования: Ubuntu/Debian, Python 3.8+, ffmpeg, TeamTalk 5 SDK (папка `sdk/`, включена в репозиторий). Бот работает под обычным пользователем (не root).

```bash
git clone https://github.com/zolo-kirill/teamtalk-universal-plugin.git
cd teamtalk-universal-plugin
sudo apt-get install -y ffmpeg python3 python3-pip python3-venv
bash install.sh          # окружение, .secrets/.env, systemd-сервис tt-plugin
# заполнить в config.json адрес сервера, токены и путь к кукам
bash run.sh
```

`install.sh` создаёт пользовательский systemd-сервис `tt-plugin` с автозапуском. Далее:

```bash
systemctl --user status tt-plugin       # статус
systemctl --user restart tt-plugin      # перезапуск
journalctl --user -u tt-plugin -f       # логи
loginctl enable-linger $(id -un)        # работа сервиса после перезагрузки
```

При перезапуске TeamTalk-сервера бот ожидает открытия порта; оборванное соединение восстанавливается: зависший коннект ватчдог разрывает по истечении `server.connect_timeout_sec` (по умолчанию 20 с), сервис поднимает бота заново. Дополнительно бот перезапускается ежедневно в 03:00 по Москве.

## Файлы

- `bot.py` — основной модуль бота.
- `tt_register.py` — регистратор учётных записей, запускается из bot.py.
- `run.sh` — скрипт запуска; `install.sh` — установщик.
- `config_default.json` и `config.json` — эталонный и рабочий конфигурационные файлы.
- `radio/` — плейлисты радиостанций; `geo/ru_ipv4.txt` — диапазоны IP-адресов РФ для гео-фильтра.
- `sdk/` — TeamTalk 5 SDK.
