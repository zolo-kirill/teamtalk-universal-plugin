# teamtalk-universal-plugin

Бот для TeamTalk 5, который я держу на своём сервере. Играет музыку и другое аудио в голосовой канал, следит за сервером и докладывает в Telegram, сам отшивает ботнетов и принимает заявки на новые учётные записи.

Звук уходит в канал как голос (вставка аудиоблоков), так что звуковая карта боту не нужна — хватает ffmpeg. Играет в стерео: если канал на сервере настроен на стерео-кодек, звук идёт как есть, 48 кГц.

Управление — командами со слэшем. В TeamTalk и в Telegram они одни и те же; в TeamTalk команды шлются личным сообщением боту.

## Музыка

- `/play <запрос или ссылка>` — найти и сыграть. Просто вставленную ссылку (в личку боту или в канал) бот тоже играет.
- `/u <ссылка>` — сыграть именно ссылку (а не искать по тексту); то же, что вставить её напрямую.
- Ссылка на плейлист YouTube или Яндекс.Музыки ставит в очередь весь плейлист, а не только начало.
- `/playlist` — что сейчас в плейлисте, постранично.
- `/stop` — стоп, `/skip` — пропустить трек, `/v <5–100>` — громкость, `/sf 30` и `/sf -30` — перемотать вперёд и назад, `/sb 66` — перемотать назад на 66 секунд.
- `/radio` — станции, `/fav` — избранное (добавляется `/fav +` или `f +`).
- `/lf <путь>` — сыграть файл с диска бота; `/dl` — отдать текущий трек файлом в канал (радио и потоковое так не отдать). Трек качается как есть, без перекодирования в mp3 (обычно opus/webm — так быстрее и качество выше); mp3 бот собирает на лету, только когда отдаёт файл по `/dl`.
- `/vo` — озвучивать название трека перед стартом.
- Сервисы: `/sv yt` — YouTube, `/sv ym` — Яндекс.Музыка. Всё ищется и играется по умолчанию на YouTube, для YM нужен токен (см. «Конфигурация»). Прямые ссылки на треки YM тоже играют.
- Не скачалось? Бот сам пробует ролик запасными клиентами YouTube, а раз в сутки проверяет свежую версию yt-dlp и обновляет её. Возрастные видео YouTube с сервера не играют — YouTube требует вход в аккаунт и режет сессии с серверных IP.
- `/login` — статус входа в YouTube и как войти своим аккаунтом. Бот принимает экспорт кук из браузера (Netscape-формат, например расширение Get cookies.txt): пришли текст экспорта боту в Telegram или файлом `.txt` — он сам сохранит его в `yt_cookies.txt`, проверит и будет пробовать им. Возрастные ролики с серверного IP Google всё равно режет — это ограничение YouTube, а не бота.

## Бот на сервере

- Личные сообщения пользователей (не команды) бот пересылает админам в Telegram — можно ответить прямо оттуда, ответ уйдёт пользователю в личку.
- Входы и выходы с сервера, кики и заявки регистратора приходят в Telegram, если настроен бот-реле.
- Кого не приветствовать сетевым сообщением и не анонсировать вход/выход — впиши в `telegram.ignore_nicks` (по нику, например `stats`) или `telegram.ignore_usernames` (по логину) в конфиге.
- `/sub` — пользователь подписывается на уведомления о входе/выходе; `/sub mus` — на присылку играющих треков в личку.
- `/online` — кто сейчас на сервере; в Telegram у каждого есть кнопки «написать», «кикнуть», «забанить».
- `/net <текст>` — broadcast-сообщение всем на сервере.
- `/admins`, `/subs` — кто админ и кто подписан. Назначить владельца можно только правкой `telegram.owner_user_id` в конфиге.
- Регистратор — отдельный Telegram-бот. Пользователь шлёт ему логин и пароль, админ жмёт «Принять» — бот создаёт учётку на сервере и присылает пользователю файл `.tt`. Админ может завести учётку и сам, командой `/create`.

## Защита от ботнетов

На публичные TeamTalk-серверы массово лезут боты под гостевой учёткой. Секция `guard` в конфиге проверяет гостей (учётки из `guest_logins` плюс всегда пустой логин) и режет тех, кто:

- заходит с пустым ником, ботнет-ником, ником-простынёй длиннее `max_nick_len` символов или с матом в нике;
- долбится с кучи IP за короткое время (`burst`);
- лезет не из разрешённых стран (`geo`, по умолчанию Россия).

Своих — себя, админов, легитимных ботов — впиши в `trusted`, чтобы защита их не трогала. Пойманных бот кикает и, если есть права админа, банит по IP. Отчёт о срабатываниях шлёт в Telegram одним сообщением на всплеск, а не на каждый кик.

## Конфигурация

Настройки лежат в двух файлах рядом с ботом: `config_default.json` (эталон, в репозитории) и `config.json` (рабочий, поверх эталона; в git не хранится, потому что там твои токены и пароли). Бот читает `config.json`, затем переменные окружения, затем значения по умолчанию.

Секции конфига:

- `server` — подключение к TeamTalk: адрес, порты, ник, логин, пароль, канал.
- `playback` — громкость по умолчанию и вывод звука (`pulse_sink`, если играть через PulseAudio).
- `runtime` — сервис по умолчанию, команды при старте, лимиты плейлиста.
- `services` — токен Яндекс.Музыки и пути к кукам YouTube и Rutube.
- `telegram` — токен бота-реле, твой Telegram ID, чат для уведомлений, имя сервера.
- `welcome` — текст «ознакомься, пожалуйста, с правилами».
- `registration` — настройки бота-регистратора.
- `guard` — защита от ботнетов, см. выше.

Ник, сервис и громкость меняются на лету (`/cn`, `/sv`, `/v`) и держатся до перезапуска. Чтобы запомнить надолго — сохрани командой `/sc`: она пишет в `config.json` ник, сервис и громкость. Конфиг поправил руками — перезапусти бота командой `/rs`.

Секреты — отдельно, в `../.secrets/.env` (папкой выше бота): токены Telegram-ботов и TeamTalk-переменные. Токен Яндекс.Музыки живёт в `services.ym.token`. Куки YouTube (Netscape-формат) — файлом `yt_cookies.txt`, путь к нему в `services.yt.cookiefile_path`.

## Установка и запуск

Нужны Ubuntu/Debian, Python 3.8+, ffmpeg и TeamTalk 5 SDK (папка `sdk/`, уже в репозитории). Бот работает под обычным пользователем, не под root.

```bash
git clone https://github.com/zolo-kirill/teamtalk-universal-plugin.git
cd teamtalk-universal-plugin
sudo apt-get install -y ffmpeg python3 python3-pip python3-venv
bash install.sh          # окружение, .secrets/.env, systemd-сервис tt-plugin
# впиши в config.json адрес сервера, токены и путь к кукам
bash run.sh
```

`install.sh` ставит пользовательский systemd-сервис `tt-plugin` с автозапуском. Дальше:

```bash
systemctl --user status tt-plugin       # статус
systemctl --user restart tt-plugin      # перезапуск
journalctl --user -u tt-plugin -f       # логи
loginctl enable-linger $(id -un)        # чтобы сервис жил после перезагрузки
```

Если сервер TeamTalk перезапускается, бот сам дождётся его порта, а оборванное соединение переживёт: зависший коннект ватчдог рвёт за `server.connect_timeout_sec` (по умолчанию 20 с), и сервис поднимает бота заново. На всякий случай бот перезапускается каждую ночь в 03:00 по Москве.

## Файлы

- `bot.py` — сам бот.
- `tt_register.py` — регистратор учёток, запускается из bot.py.
- `run.sh` — обёртка запуска, `install.sh` — установщик.
- `config_default.json` и `config.json` — конфиг (эталон и рабочий).
- `radio/` — плейлисты радиостанций, `geo/ru_ipv4.txt` — диапазоны РФ для гео-фильтра.
- `sdk/` — TeamTalk 5 SDK.
