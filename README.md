# teamtalk-universal-plugin

Бот для сервера TeamTalk 5. Обеспечивает воспроизведение музыки и иного аудио в голосовом канале, приём голосовых сообщений из Telegram, контроль состояния сервера с уведомлениями в Telegram, защиту от автоматизированных подключений и обработку заявок на учётные записи.

Звук передаётся в канал как голосовой поток (вставка аудиоблоков), поэтому звуковая карта не требуется — достаточно ffmpeg.

Управление выполняется командами с косой чертой. Набор команд един для TeamTalk и Telegram; в TeamTalk команды направляются боту личным сообщением. В Telegram дополнительно доступна панель управления на кнопках.

## Музыка

- `/play <запрос или ссылка>` — поиск и воспроизведение. Ссылка, направленная боту личным сообщением или в канал, также воспроизводится.
- Ссылка на плейлист YouTube или Яндекс.Музыки добавляет в очередь весь плейлист, а не только первый трек.
- `/mow` (она же `/волна`) — «Моя волна» Яндекс.Музыки: очередь наполняется треками личной волны.
- **Потоковые ссылки** (радио, `.m3u8`, `.pls`, ответы с заголовками `icy-*`) воспроизводятся напрямую через ffmpeg, без предварительной загрузки: поток не имеет окончания, поэтому загрузка неприменима.
- `/playlist` — содержимое очереди, постранично.
- `/stop` — остановка, `/skip` — переход к следующему треку, `/v <5–100>` — установка громкости, `/sf 30` и `/sf -30` — перемотка вперёд и назад.
- `/radio` — список станций (111), `/fav` — избранное (добавление: `/fav +` или `f +`).
- `/lf <путь>` — воспроизведение файла с диска бота; `/dl` — отправка текущего трека файлом в канал (для радио и потоковых источников недоступно).
- `/vo` — озвучивание названия трека перед началом воспроизведения.
- Сервисы: `/sv yt` — YouTube, `/sv ym` — Яндекс.Музыка. По умолчанию поиск и воспроизведение выполняются на YouTube; для Яндекс.Музыки требуется токен (см. раздел «Конфигурация»). Прямые ссылки на треки Яндекс.Музыки также поддерживаются.
- **Автопродолжение**: последний воспроизведённый объект (трек или радиостанция) сохраняется в `last_played.json` и возобновляется через 5 секунд после перезапуска. Ручная остановка (`s` или кнопка ⏹) отменяет возобновление.
- **Ограничение для гостевых учётных записей**: учётные записи «гость»/«guest» получают ответ «Гостям управление недоступно» и не могут управлять воспроизведением.

## Панель управления в Telegram

Команда `/panel` (она же `/пульт`) направляет сообщение с кнопками:

| Ряд | Кнопки |
|---|---|
| 1 | ⏸ Пауза / ▶️ Продолжить · ⏭ Следующий · ⏹ Стоп |
| 2 | 🔉 −10 · 🔊 +10 · 📋 Очередь |
| 3 | 🔄 Обновить · 👥 Онлайн |

Нажатие кнопки выполняет действие и обновляет панель в том же сообщении: сведения о треке, позиция и громкость изменяются на месте. Панель доступна владельцу и администраторам.

## Голосовые сообщения из Telegram

Голосовое сообщение загружается (`.oga`), конвертируется в mp3 48 кГц/стерео и воспроизводится в канале; в ответ направляется строка «Голосовое 3 с — воспроизвожу в канале “/”».

Если в канале уже воспроизводится аудио, громкость основного потока снижается до значения `music.voice_duck` (по умолчанию 20%), поверх воспроизводится голосовое сообщение, после чего громкость восстанавливается. Очередь и текущий трек при этом не изменяются.

Звук бота доступен только пользователям, находящимся в том же канале, что и бот. По умолчанию бот находится в корневом канале `/`.

## Голосовое приветствие (Silero TTS)

При входе пользователя бот воспроизводит приветствие синтезированной речью. Текст задаётся параметром `welcome.voice_text` и может содержать подстановки `{nick}` и `{server}`.

- Синтез выполняется локально средствами **Silero TTS** (`v4_ru`); доступ в интернет и ключи не требуются, вычисления выполняются на CPU.
- Синтез вынесен в **отдельный процесс** (`tts_worker.py`, юнит `tt-plugin-tts.service`) и взаимодействует с ботом через unix-сокет `cache/tts.sock`. Причина: совместная работа torch и TeamTalk SDK в одном процессе приводит к аварийному завершению через несколько секунд после подключения к серверу. При отсутствии воркера бот работает в обычном режиме, без голосового приветствия.
- При воспроизведении музыки громкость основного потока снижается до 15% на время фразы и затем плавно восстанавливается: приветствие подмешивается в общий PCM-поток, отдельный канал не требуется.
- При отсутствии воспроизведения приветствие звучит отдельным потоком.
- Результат синтеза кэшируется в каталоге `cache/`; повторные входы воспроизводятся мгновенно.
- Для гостевых и служебных учётных записей приветствие не воспроизводится. Значение `welcome.voice_cooldown: 0` (по умолчанию) соответствует приветствию при каждом входе; значение больше нуля задаёт интервал в секундах между приветствиями одному пользователю.
- Длительность фразы по умолчанию — около 11 секунд (157 символов). Синтез на прогретой модели занимает около 3 секунд, далее используется кэш `cache/greet_<hash>.raw`.

Требования: torch (CPU-сборка) и numpy.

```bash
.venv/bin/pip install --index-url https://download.pytorch.org/whl/cpu torch numpy
```

Доступные голоса: `baya`, `kseniya`, `xenia`, `eugene`, `aidan` (параметр `welcome.voice_speaker`).

## Работа с сервером

- Личные сообщения пользователей (за исключением команд) пересылаются администраторам в Telegram; ответ из Telegram направляется пользователю в личные сообщения.
- Уведомления о входах и выходах, отключениях и заявках регистратора направляются в Telegram при настроенном боте-реле.
- `/sub` — подписка на уведомления о входе и выходе; `/sub mus` — подписка на сведения о воспроизводимых треках.
- `/online` — список пользователей на сервере; в Telegram для каждого доступны кнопки «написать», «кикнуть», «забанить».
- `/net <текст>` — broadcast-сообщение всем пользователям сервера.
- `/admins`, `/subs` — списки администраторов и подписчиков. Назначение владельца выполняется только изменением параметра `telegram.owner_user_id` в конфигурации.
- **Тихий режим** (`runtime.quiet_playback`): служебные сообщения («добавлено в очередь», «сейчас играет», «очередь пуста») не направляются в канал и личные сообщения, а только записываются в журнал. Ответы на команды сохраняются.
- Изменение прав учётной записи определяется автоматически. Если пользователь находится на сервере, ему направляется уведомление о необходимости повторного входа, после чего по истечении заданного интервала выполняется отключение: новые права применяются сервером только при следующем подключении. Интервал задаётся параметром `account_watch.notice_delay_sec` (по умолчанию 5 секунд; значение 0 — отключение без задержки).
- Регистратор — отдельный Telegram-бот. Пользователь направляет логин и пароль, администратор подтверждает заявку, после чего учётная запись создаётся на сервере, а пользователю направляется файл `.tt`. Создание учётной записи администратором доступно командой `/create`.

## Защита от автоматизированных подключений

На публичных серверах TeamTalk регулярно выполняются массовые подключения автоматизированных клиентов под гостевой учётной записью. Секция `guard` конфигурации проверяет подключившихся и отключает тех, кто:

- подключается с пустым ником (`kick_empty_nick`). Правило применяется к **любой** учётной записи: подключение без ника неотличимо от анонимного. Отключение проверки для негостевых учётных записей — `kick_empty_nick_all: false`; отключение без блокировки IP вместо блокировки — `kick_empty_nick_ban: false`;
- подключается под гостевой учётной записью (логины из `guest_logins`, пустой логин) при совпадении ника с базой ботнетов, длине ника свыше `max_nick_len` символов или наличии нецензурной лексики;
- выполняет массовые подключения с множества IP-адресов за короткий интервал (`burst`);
- подключается из стран, отсутствующих в списке разрешённых (`geo`, по умолчанию Россия).

Проверки ника, лексики, географии и всплеска подключений применяются только к гостевым учётным записям, поскольку могут затрагивать добросовестных пользователей; проверка пустого ника ложных срабатываний не имеет. Доверенные учётные записи (администраторы, легитимные боты) указываются в `trusted`. При срабатывании выполняется отключение, а при наличии прав администратора — блокировка по IP. Отчёт направляется в Telegram одним сообщением на всплеск, а не на каждое отключение.

### Двуязычная озвучка

Латинские слова синтезируются английской моделью Silero (`v3_en`), кириллица — русской (`v4_ru`). Воркер разделяет фразу по алфавиту и объединяет фрагменты с паузой 80 мс:

```
Играет: Matt Nash - Know My Love
   ru | Играет:
   en | Matt Nash - Know My Love
```

- `welcome.voice_bilingual` — `true` (по умолчанию). Значение `false` включает транслитерацию латиницы в кириллицу (без второй модели).
- `welcome.voice_en_speaker` — английский голос, по умолчанию `en_21` (доступно 119 голосов: `en_0`…`en_117` и именные — мужские и женские).
- Русский голос изменяется командой `/voice` в Telegram, английский — только через конфигурацию.

Память: обе модели размещаются в воркере (~200 МБ); первая загрузка английской модели занимает около 25 секунд, последующий синтез выполняется без задержки.

## Воспроизведение при запуске

Воспроизведение сразу после запуска задаётся в `config.json`:

```
"startup": {
  "url": "https://example.com/stream.mp3",
  "volume": 3,
  "resume_last": false
}
```

- `url` — ссылка для воспроизведения при старте (поток воспроизводится напрямую, файл загружается). Пустая строка — воспроизведение не запускается.
- `volume` — громкость сразу после входа в канал, 1–100. Значение `0` — параметр не изменяется, остаётся `playback.default_volume`.
- `resume_last` — значение `true` возобновляет воспроизведение предыдущего объекта после перезапуска. По умолчанию `false`: бот запускается без воспроизведения.

## Озвучивание названий треков (Silero TTS)

При старте трека бот называет его голосом поверх музыки:

- громкость музыки снижается до `welcome.voice_duck` (15%), воспроизводится фраза, затем громкость плавно восстанавливается;
- голос совпадает с голосом приветствия и изменяется командой `/voice`;
- латиница синтезируется английской моделью; при отключённой двуязычной озвучке выполняется транслитерация в кириллицу, поскольку модель `v4_ru` не распознаёт латинские слова (проверено: «Играет: Matt Nash - Know My Love» синтезировалось как «Играет», 0.85 с вместо 2.46 с);
- длинное название обрезается до 120 символов;
- функция включается и отключается командой `vo` (флаг в `.voice_announce`), по умолчанию включена (ключ `music.voice_announce` в конфигурации);
- при отсутствии воспроизведения название не озвучивается.

## Конфигурация

Настройки размещаются в двух файлах: `config_default.json` (эталонный, хранится в репозитории) и `config.json` (рабочий, имеет приоритет; в git не хранится, поскольку содержит токены и пароли). Порядок чтения: `config.json`, переменные окружения, значения по умолчанию.

Секции конфигурации:

- `server` — подключение к TeamTalk: адрес, порты, ник, логин, пароль, канал.
- `playback` — громкость по умолчанию и вывод звука (`pulse_sink` при выводе через PulseAudio; пустое значение — бот передаёт PCM в TeamTalk напрямую).
- `runtime` — сервис по умолчанию, команды при старте, лимиты очереди, `quiet_playback` (тихий режим).
- `services` — токен Яндекс.Музыки и пути к кукам YouTube и Rutube.
- `telegram` — токен бота-реле, идентификатор владельца, чат для уведомлений, название сервера.
- `welcome` — текст «ознакомься, пожалуйста, с правилами» и голосовое приветствие: `voice_enabled`, `voice_text` (шаблон с `{nick}` и `{server}`), `voice_speaker`, `voice_duck`, `voice_cooldown`, `silero_model`.
- `registration` — параметры бота-регистратора.
- `account_watch` — контроль прав учётных записей: интервал опроса, уведомление владельцу в Telegram, пауза перед отключением.
- `guard` — защита от автоматизированных подключений.

Ник, сервис и громкость изменяются без перезапуска (`/cn`, `/sv`, `/v`) и сохраняются до перезапуска. Для долговременного сохранения используется команда `/sc`, записывающая ник, сервис и громкость в `config.json`. После ручного изменения конфигурации требуется перезапуск командой `/rs`.

Секреты хранятся отдельно, в `../.secrets/.env` (каталог выше каталога бота): токены Telegram-ботов и переменные TeamTalk. Токен Яндекс.Музыки размещается в `services.ym.token`. Куки YouTube (формат Netscape) — файл `yt_cookies.txt`, путь указывается в `services.yt.cookiefile_path`.

## Установка и запуск

Требования: Ubuntu/Debian, Python 3.10+. Бот работает под обычной учётной записью; запуск от root не требуется.

```bash
git clone <адрес репозитория>
cd teamtalk-universal-plugin
bash install.sh
```

`install.sh` выполняет следующие действия:

1. устанавливает пакеты: `ffmpeg`, `python3` с `pip`/`venv`, `curl`, `ca-certificates`, `wget`, `unzip`, `git`, `p7zip-full`;
2. создаёт `.venv` и устанавливает `requests`, `yt-dlp`, `yandex-music`, обновляет `pip`/`wheel`, предлагает установить Deno (требуется yt-dlp для YouTube);
3. **загружает актуальную версию TeamTalk 5 SDK с bearware.dk** и проверяет её работоспособность: `readelf` по требуемой версии glibc → `ctypes.CDLL` → импорт `TeamTalk5`. При несовместимости используется следующая сборка, в крайнем случае — SDK из репозитория. Сборка 5.23a для Ubuntu 26 требует glibc 2.43, поэтому на Ubuntu 24 установщик использует 5.22a;
4. **настраивает обход блокировки Telegram**: при недоступности `api.telegram.org` запрашивает `vless://`, `vmess://`, `trojan://` или готовый `socks5://`/`http://`, устанавливает Xray-core, формирует конфигурацию (tcp/ws/grpc/xhttp/httpupgrade, tls и reality), проверяет `xray run -test` и контрольным запросом, после чего записывает `TG_PROXY` в `.secrets/.env`. При неудаче предлагается следующий ключ;
5. запрашивает адрес сервера, учётную запись бота и пароль, создаёт `.secrets/.env` и systemd-сервис `tt-plugin` с автозапуском и `linger`.

Дальнейшие команды:

```bash
systemctl --user status tt-plugin       # статус
systemctl --user restart tt-plugin      # перезапуск
journalctl --user -u tt-plugin -f       # журнал
loginctl enable-linger $(id -un)        # работа сервиса после перезагрузки
```

При перезапуске сервера TeamTalk бот ожидает открытия порта; разрыв соединения обрабатывается: зависшее подключение прерывается по таймауту `server.connect_timeout_sec` (по умолчанию 20 секунд), после чего сервис перезапускает бота. Дополнительно бот перезапускается каждую ночь в 03:00 по Москве.

## Состав файлов

- `bot.py` — основной модуль бота.
- `tt_register.py` — регистратор учётных записей, запускается из `bot.py`.
- `run.sh` — обёртка запуска, `install.sh` — установщик.
- `config_default.json` и `config.json` — эталонная и рабочая конфигурация.
- `radio/` — плейлисты радиостанций, `geo/ru_ipv4.txt` — диапазоны IP-адресов РФ для гео-фильтра.
- `sdk/` — TeamTalk 5 SDK.
- `last_played.json` — последний воспроизведённый объект для автопродолжения (в git не хранится).
- `cache/`, `inbox/` — кэш и принятые файлы (в git не хранятся).
